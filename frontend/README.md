**Tech Stack:** React 19, Vite 8, Deck.gl 9, MapLibre GL, Lucide React, Oxlint

## 1. Overview

The TerraSpectra Frontend is a modern, responsive web application and GIS dashboard engineered to visualize hyperspectral crop stress analytics, disease-risk forecasting, and spatial field metadata. It connects to the FastAPI backend service (Kanishka) and displays inference outputs generated by the 3D-CNN / ViT machine learning models (Harsh & Khushi).

### Key Features (Week 2 Deliverables):
- **Interactive Deck.gl Geospatial Map:**
  - Multi-layer rendering for prediction polygon tiles, stress alert highlights, and field boundary grids.
  - Carto Positron basemap via MapLibre GL in WGS-84 / EPSG:4326.
  - Interactive click and hover inspection with visual high-contrast gold selection rings.
- **Dynamic Layer Visibility Controls:**
  - Granular toggling of Prediction Polygons, Stress Alerts, and Grid Boundaries with active layer counts.
- **Spectral Prediction Legend:**
  - Color-coded indicators reflecting confirmed ML categories (`Healthy`, `Stressed Alert`, `NoData`) with distinct provisional demo tags.
- **Feature Details Panel:**
  - Deep inspection of selected features: stable ID, confidence score, uncertainty estimation, scene metadata (sensor, acquisition date, CRS, patch grid), and model provenance.
  - Clear selection reset action.
  - Graceful handling of missing metadata (explicit "Not provided" or "Pending scene intake", never fake placeholders).
- **Centralized API Client & Switchable Mock Adapter:**
  - Automatic fallback to mock mode when `VITE_API_BASE_URL` is unset.
  - Structured error parsing for FastAPI/Pydantic validation errors (`HTTP_422`) and backend error envelopes.
  - Zero-config local development without requiring a live GPU server.
- **Zero-Dependency Test Suite:**
  - 29 unit and integration tests running on Node.js native test runner (`npm test`).

## 3. Environment Configuration & Mock vs. Real Mode

The frontend automatically toggles between **Mock Mode** and **Live Backend Mode** based on `frontend/.env`.

### Local Mock Mode (Default)
When `VITE_API_BASE_URL` is omitted or empty:
```env
# frontend/.env
VITE_API_BASE_URL=
```
- The frontend operates with an internal mock adapter.
- Responses conform strictly to the backend `StandardResponseEnvelope` and ML taxonomy.
- All mock data is stamped with `_isMock: true` and labeled with demo banners to ensure mock data is never mistaken for real crop predictions.

### Live Backend Mode
To connect to Kanishka's running backend service:
```env
# frontend/.env
VITE_API_BASE_URL=http://localhost:8000
```
- Direct REST calls are dispatched to `/health`, `/api/v1/system/status`, and `/api/v1/analyze`.
- Network errors, timeouts, and Pydantic validation errors are automatically captured and presented with retry actions.

## 4. Geospatial & ML Data Contract

### Coordinate Reference System (CRS)
- **Standard:** `EPSG:4326` (WGS-84).
- **Coordinate Order:** `[longitude, latitude]` per GeoJSON RFC 7946 (e.g., `[80.205, 13.085]`).
- **Bounding Box:** `[min_lon, min_lat, max_lon, max_lat]`.

### Classification Taxonomy
Aligned with `ml/configs/classes.yaml` by Harsh:
- **Class 0 (`healthy`):** Normal spectral reflectance; emerald green fill.
- **Class 1 (`stressed`):** Red-edge / water-absorption anomaly; coral red fill; tagged with **Alert Class**.
- **Class -1 (`unclassified_nodata`):** Background or cloud mask; neutral slate fill.
- **Provisional Demo Classes (`demo`, `uncertain`):** Used only in mock mode; clearly tagged with a "Provisional" badge.
